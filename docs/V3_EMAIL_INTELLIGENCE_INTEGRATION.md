# V3 AI 邮件情报融入现有项目评审

## 钉钉企业邮箱接入（2026-08-02）

- 收件：`imap.qiye.aliyun.com:993`，强制 SSL。
- 发件：`smtp.qiye.aliyun.com:465`，强制 SSL；当前仅做登录与连通性验证，不自动发送邮件。
- 配置并启用后默认每 5 分钟同步最近 50 封邮件，也支持页面手动触发。
- 完整 `.eml` 原件、正文、Header、收发件人、抄送、线程和附件分别保存；同一账号与 Message-ID 组合去重。
- 邮件先进入原始数据层，再做规则分析、项目匹配和活动生成；低置信度邮件进入人工确认。
- 账号密码或客户端授权码仅放在后端 `.env`，不得提交到源代码。

## 结论

现有系统不需要重构。项目、客户、渠道、报价继续作为业务主数据；活动日志继续作为统一时间轴；日报和邮件作为两类独立原始数据源，在完成可靠项目归属后生成活动。

## 分层边界

1. 原始事实层
   - `email_messages` 保存邮件正文、信头、收发件人、线程及供应商原始载荷。
   - `email_attachments` 保存附件元数据、存储位置和提取状态。
   - 原始字段只追加，不由分析或人工修正覆盖。

2. 分析层
   - 项目匹配方式、匹配分、摘要、客户诉求、态度、行动项、风险和分析版本。
   - 分析结果允许重新生成，必须保留分析版本。

3. 业务层
   - 项目、客户、渠道、报价及人工确认后的阶段/状态。
   - 已可靠关联的邮件通过 `activity_logs.source=邮件` 进入项目时间轴。

## 首期已实现

- 邮件原始数据与附件数据模型。
- 邮件列表、接入状态、测试导入、人工项目确认接口。
- 已确认线程继承或邮件主题精确匹配才自动绑定；正文包含和模糊结果不自动绑定。
- 未匹配邮件进入待确认。
- 自动或人工可靠关联后生成邮件来源活动。
- 规则/AI风险只作为建议保存，不自动生成阻塞事实或改变项目健康度。
- 项目归属被人工纠正时同步迁移时间轴活动，并记录操作者、前后项目和原因。
- 管理员、项目经理可管理邮件；其他角色只能查看自己负责项目的已关联邮件。
- 原始正文和分析结果在页面分区展示。
- Gmail OAuth 配置入口；不保存邮箱密码。

## Gmail 接入后续工作

1. 在 Google Cloud 建立 OAuth 客户端并启用 Gmail API。
2. 使用最小只读权限读取共享项目邮箱。
3. 加密保存 refresh token，禁止保存邮箱密码。
4. 通过 Gmail historyId 做增量同步，以 message id 做幂等去重。
5. 下载附件后计算 SHA-256，再进入 OCR/文档解析队列。
6. 同步、附件解析、AI 分析均使用后台任务，不阻塞页面。

## AI 分析后续工作

- 将当前 `rules-v1` 规则初析替换为结构化 AI 输出。
- 每次分析写入模型、提示词版本、时间和证据。
- AI 只提出项目阶段、健康度和风险建议，不直接修改关键业务字段。
- 邮件线程一旦人工确认项目，后续同线程默认继承归属。
- 项目知识库优先保存确认事实、联系人、线程、决策与未完成行动项，再增加向量检索。

## 推荐实施顺序

1. Gmail OAuth、增量同步、幂等和失败重试。
2. 邮件线程继承、联系人/域名特征库。
3. AI 结构化摘要、诉求、行动项、风险和证据。
4. 附件落盘、文本提取、分类和摘要。
5. 风险中心及 Dashboard 聚合。
6. 项目知识库和跨邮件线程分析。

## 日报 AI 同步补充（2026-08-01）

- 日报同步改为两阶段：先将外部接口返回内容写入 `daily_report_raw_entries`，再调用 DeepSeek 分析。
- 原始载荷与 AI 分析结果分列保存，AI 失败不回滚已拉取日志。
- 已有人工绑定优先；未绑定项目只有 DeepSeek 置信度达到 0.92 才自动绑定，否则进入人工确认。
- 活动 `occurred_at` 优先使用原始日志里的实际发生/创建时间；无时间字段时才回退到接口查询日期中午。
- 历史已导入日志重新分析时更新原活动，不重复创建活动。
- AI 给出的风险或阻塞类型不会自动设置 `blocker_flag`，避免直接影响项目健康度。
